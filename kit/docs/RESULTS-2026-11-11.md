> 记录日期：2026-11-11。所有数字来自本包内这份代码在两台独立主机上的实跑。
> 涉及主机 IP、本机路径等信息一律以占位符代替，不在此文档出现。

## 一句话结论

- 同一份体验包代码，在**两台独立主机**上分别跑通全链（`verified=true`，4/4 完成）。
- 两台主机的固件 dump **逐字节一致**：90/90 个 title，name/size/sha256 全部相同（0 mismatch）。
- 命中率统计：**每合格波 22.6%**，与作者在 SmileBASIC 上报告的 ~20%/波一致。

## 本轮代码变更（补丁 11/12，详见 CHANGES.md）

- **补丁 11**：drift 容忍放宽——`earlyHole` 或 `|Δ| ≤ 0x8000` 视为可重试（reason：
  early-hole / small-drift / known-magnitude）；超过 0x8000 仍按作者原逻辑 fatal。
- **补丁 12**：cleanup-gated 同 boot 重试完整回植（吸收 x43x61x69/ns2jb `e3309c3`）——
  清理未被证明或 placement 不确定时不再同 boot 连败 3 次，直接要求重启。
  RUN 53 实测：脏 attempt 只跑 1 次即退（旧逻辑会拖约 8 分钟并推主机入 wedge）。

## 给复刻者的要点（常见判读）

1. **1/4 全过 + 2/4 失败 = 环境没问题**，只是 ~30%/boot 的概率门。按标准循环重抽
   （硬重启 → 重建触发存档 → 再硬重启 → `-SkipRestore` 跑）。
2. 双端必须**有线网络**（竞态时序敏感）；不要在同一个 boot 里连续重跑（脏存档命中率归零）。
3. 成功判据只看 PC 端：`verified=true` + `FS execution verified...`；
   屏幕上的 `Executed successfully` 只是单次 bridge 会话正常收尾，成功失败都会出现。
4. 本包不随附固件 dump 二进制；需要时在成功轮加 `-FirmwareDump` 自行生成（90 个 title / 222 MB）。
